4.3 内存管理

前面两节我们把内存地址和指针都摸清了，我们知道，C和C++是及其自由的语言，指针更是如此。

写 int a = 10;，编译器自动帮你安排好地方；出了花括号（3.1 学过），它又自动收回去。既不用申请，也不用归还。

但有一些事情，需要手动操控内存才能做到。

两块内存：栈与堆#

4.1 说内存是一长排小格子。其实这排格子被划分成了好几块区域，我们现在只需要关心其中两块：

  • 栈（stack）：函数(如main)开始时自动分配，出了域自动回收。；
  • 堆（heap）：要你自己申请、自己释放，完全归你管。

使用C语言的内存控制，需要在最顶上加一行#include <stdlib.h>

C#

#include <stdio.h>
#include <stdlib.h>
int main(){
	int a = 10;							// 栈上的变量
	int *p = malloc(sizeof(int));		// 堆上的一块内存，参数填申请内存大小
	*p = 20;

	printf("栈上 a 的地址：%p\n", &a);
	printf("堆上 *p 的地址：%p\n", p);

	free(p);
	return 0;
}

C++#

如果C语言想用malloc等，可以在最顶上加一行#include <cstdlib>而不是#include <stdlib.h>

同时，malloc的值最后其实是一个void*的类型，所以C可以省略类型转换，但在C++中必须强制类型转换成对应的指针类型。

#include <iostream>
#include <cstdlib>
int main(){
	int a = 10;					// 栈上的变量
	int *p = (int*)malloc(sizeof(int));		// 堆上的一块内存
	*p = 20;

	std::cout << "栈上 a 的地址：" << &a << "\n";
	std::cout << "堆上 *p 的地址：" << p << "\n";

	free(p);
	return 0;
}

运行结果：

栈上 a 的地址：000000D0FA9FFCC4
堆上 *p 的地址：00000220EBA0CBC0

多跑几次就更清楚了，下面是黑兔的机器连续 4 次的结果：

规律很明显：栈地址都在 000000 那一段，堆地址都在 000001、000002 那一段

两者在进程的地址空间里离得非常远，本来就是两片不同的区域。

而且每次运行两个地址都在变，和 4.1 讲的“地址每次运行都不一样”是同一个道理。

申请内存：malloc#

堆内存要自己申请。用的工具是 malloc（memory allocation，内存分配）

给它一个字节数，它就还你一块那么大的连续内存，返回这块内存的起始地址；内存不够就返回 NULL。

先申请一个 int 试试：

#include <stdio.h>
#include <stdlib.h>
int main(){
	int *p = (int*)malloc(sizeof(int));		// 申请 4 个字节
	if (p == NULL) {				// 申请失败会返回 NULL
		printf("内存申请失败\n");
		return 1;
	}

	*p = 42;					// 和普通指针一样解引用
	printf("*p = %d\n", *p);

	free(p);					// 用完必须还回去
	p = NULL;					// 可以顺手置空，防止误用
	return 0;
}

运行结果：

*p = 42

四个要点：

  • 返回值是 void*，所以要转成 int* 才能用。C 里这个转换可以省，C++ 里必须写；
  • 不推荐写 malloc(4)。换台电脑 int 可能不是 4 个字节，写 sizeof(int) 就不用担心了；
  • 申请可能失败，内存不是无限的，所以建议检查 p == NULL；
  • 用完必须还。

C99 起 C 支持变长数组 int a[n];，但它是栈上的：n 大一点直接爆栈，而且 C++ 根本不支持。真要在运行时定长度，还是用 malloc。

注意 a[i] 这种写法：a 明明只是个指针，却能像数组一样下标。下一节会具体讲解。

calloc：顺便清零#

malloc 申请出来的内存是“脏”的：里面躺着上一次谁用过之后留下的内容。想拿到干净的内存，用 calloc（counting allocation）：

#include <stdio.h>
#include <stdlib.h>
int main(){
	int *a = (int*)malloc(3 * sizeof(int));		// 不清零
	int *b = (int*)calloc(3, sizeof(int));		// 清零

	printf("malloc 的第一个数：%d\n", a[0]);
	printf("calloc 的第一个数：%d\n", b[0]);

	free(a);
	free(b);
	return 0;
}

本机运行结果：

malloc 的第一个数：5570627
calloc 的第一个数：0

calloc(3, sizeof(int)) 的意思是“3 个、每个 sizeof(int) 字节”，它会把整块内存全部填成 0。

C++ 没有 calloc，不过 new int[n]() 也能清零，new稍后讲解：

#include <iostream>
int main(){
	int n = 5;
	int *a = new int[n]();			// 末尾一对空括号：清零
	for (int i = 0; i < n; i++) std::cout << a[i] << " ";
	std::cout << "\n";
	delete[] a;
	return 0;
}

运行结果：

0 0 0 0 0

realloc：扩容#

内存申请少了怎么办？realloc（re-allocation）可以把一块内存变大或变小：

#include <stdio.h>
#include <stdlib.h>
int main(){
	int *a = (int*)malloc(2 * sizeof(int));
	if (a == NULL) return 1;
	a[0] = 1;
	a[1] = 2;

	int *b = (int*)realloc(a, 5 * sizeof(int));	// 扩容成 5 个 int
	if (b == NULL) { free(a); return 1; }		// 失败时旧的 a 还在
	a = b;						// 复制新地址

	for (int i = 2; i < 5; i++) a[i] = i + 1;
	for (int i = 0; i < 5; i++) printf("%d ", a[i]);
	printf("\n");

	free(a);
	return 0;
}

运行结果：

1 2 3 4 5

原来装着的 1、2 都还在，realloc 会把旧数据原样带到新的内存空间。

但它有一个必须知道的行为：它可能换内存地址。如果原来那块内存后面没有足够的地方，realloc 会另找一块够大的、把老数据搬过去、再把旧的释放掉，然后返回新地址。所以：

  • 一定要拿新的地址
  • 旧指针地址在 realloc 之后就作废了，不能再拿去用。

下面这个写法非常常见，也非常危险：

p = (int*)realloc(p, 5 * sizeof(int));		// 危险写法

如果这次扩容失败，realloc 返回 NULL，而 p 就会被赋成了 NULL

原来那块内存的地址就此丢失，一直占用内存无法释放，典型的内存泄漏。

推荐写法就是上面例子的例子，用临时变量确定了不是NULL再进行赋值。

归还内存：free#

free(p) 把 malloc / calloc / realloc 要来的内存还回去，但有一些问题：

  • 只能 free 一次；
  • 只能 free 申请来的地址：栈上的变量、数组名、p + 1 都不行；
  • free(NULL) 是安全的，什么都不做；
  • free 之后指针本身还在，但它指向的内存已经被释放掉了，这就是 4.2 说的悬垂指针。顺手加一行 p = NULL;，能省掉后面很多麻烦。

四条里唯一“安全”的就是第三条，验证一下：

#include <stdio.h>
#include <stdlib.h>
int main(){
	int *p = NULL;
	free(p);				// 释放空指针是安全的
	printf("free(NULL) 没事\n");
	return 0;
}

运行结果：

free(NULL) 没事

C++ 的写法：new 和 delete#

C++ 有一套自己的内存管理，比 malloc / free 更安全。把单个对象和数组的申请、使用、归还连起来看一遍：

#include <iostream>
int main(){
	int *p = new int(42);			// 申请一个 int，顺便放进去 42
	std::cout << "*p = " << *p << "\n";
	delete p;				// 单个对象配 delete

	int n = 5;
	int *a = new int[n];			// 申请 n 个 int
	for (int i = 0; i < n; i++) a[i] = i * i;
	for (int i = 0; i < n; i++) std::cout << a[i] << " ";
	std::cout << "\n";
	delete[] a;				// 数组配 delete[]

	return 0;
}

运行结果：

*p = 42
0 1 4 9 16

和 malloc / free 的区别：

  • new int(42) 可以顺便塞个初值，malloc 不行；
  • new 会调用构造函数、delete 会调用析构函数，malloc / free 不会（等到第六章详细讲解构造函数和析构函数）；
  • new 失败不返回 NULL，而是抛出异常 std::bad_alloc，所以 C++ 里通常不写 NULL 检查。关于异常，后面会专门讲解。

谁申请、谁释放，这张表一定要记牢：

这三组必须严格配对。new[] 出来的用 delete 释放、malloc 出来的用 delete 释放，都是未定义行为。C++ 里也能继续用 malloc / free，但不推荐，它不会调用构造函数和析构函数。

内存泄漏：申请了不释放#

第一种：压根没写 free。最容易发生的地方是循环里：

for (int i = 0; i < 200000; i++) {
	int *p = (int*)malloc(1024);		// 每轮申请 1KB
	if (p == NULL) return 1;
	p[0] = i;
}						// p 出了这个域就没了，这些内存没释放

这段代码跑完，20 万块内存一块都没还。本机实测：进程的工作集是 204.2 MB；把 free(p); 加回去，同样的 20 万次循环，只有 4.7 MB。

第二种：指针被覆盖，没有释放的机会了。

#include <stdio.h>
#include <stdlib.h>
int main(){
	int *p = (int*)malloc(sizeof(int));
	*p = 1;

	p = (int*)malloc(sizeof(int));		// 第一块内存的地址被覆盖了
	*p = 2;

	printf("%d\n", *p);
	free(p);
	return 0;
}

这里申请了两块内存，但 p 只有一个。第一次申请的地址被第二次覆盖之后，那块内存就再也找不回来了——它还在占着地方，却谁也够不着。程序照常打印 2，正常退出，什么异常也没有。

即便你添加了 -Wall 编译器也完全不会提醒你。

泄漏为什么难发现？因为它不报错、不崩溃，程序看起来一切正常，只是内存一直涨。

写个用完就退的小工具无所谓

程序进程一结束，操作系统会把它的所有内存都收回去

但服务器程序一跑几个月，早晚把内存用完。（这也是电脑开久了变卡原因之一，总有程序员内存泄漏导致不重启释放不了内存）

更严重的问题#

忘释放问题仍不算大，这里有一些更大的问题！

（1）同一块内存释放两次#

#include <stdio.h>
#include <stdlib.h>
int main(){
	int *p = (int*)malloc(sizeof(int));
	*p = 10;

	free(p);
	printf("第一次 free 完成\n");
	free(p);				// 危险：同一块内存释放两次
	printf("第二次 free 完成\n");
	return 0;
}

运行结果：

（没有任何输出，程序直接挂掉，退出码 0xC0000374：堆损坏）

打开 -Wall，编译器会提醒你：

warning: pointer 'p' used after 'free' [-Wuse-after-free]
note: call to 'free' here

（2）释放不是申请来的地址#

#include <stdio.h>
#include <stdlib.h>
int main(){
	int a = 10;
	int *p = &a;				// p 指向栈上的变量
	free(p);				// 危险：这块内存不是 malloc 来的
	return 0;
}

运行结果和上面一样，退出码 0xC0000374。-Wall 的提醒更直接：

warning: 'free' called on unallocated object 'a' [-Wfree-nonheap-object]
note: declared here

（3）释放之后接着用#

#include <stdio.h>
#include <stdlib.h>
int main(){
	int *p = (int*)malloc(sizeof(int));
	*p = 10;

	free(p);				// 内存已经还回去了
	printf("%d\n", *p);			// 危险：还在用那块已经不属于你的内存
	return 0;
}

运行结果：

-1626067504

程序没崩，退出码 0，看起来一切正常，但那个数完全是不可预测。本机连跑四次，分别打印出 -1909929056、1526582176、1274465184、1666698144，没有一次是 10。

-Wall 同样会警告：warning: pointer 'p' used after 'free' [-Wuse-after-free]。

疯狂的测试：刚还回去的内存，马上就被别人拿走了#

要理解（3）为什么危险，看下面这段就懂了：

#include <stdio.h>
#include <stdlib.h>
int main(){
	int *p = (int*)malloc(sizeof(int));
	*p = 111;
	printf("第一次申请：%p，里面是 %d\n", (void*)p, *p);

	free(p);					// 还回去

	int *q = (int*)malloc(sizeof(int));		// 再申请一块
	*q = 222;
	printf("第二次申请：%p，里面是 %d\n", (void*)q, *q);
	printf("p 和 q 是同一块吗？%c\n", (p == q) ? "Y" : "N");

	free(q);
	return 0;
}

运行结果：

第一次申请：000002AFCBC8EF80，里面是 111
第二次申请：000002AFCBC8EF80，里面是 222
p 和 q 是同一块吗？Y

free 掉的内存会被立刻回收、丢进空闲列表；下一次 malloc 张嘴要同样大小的内存，分配器大概率会把刚收回来的那块原样再给你。本机连跑两次，地址一模一样。

这就解释了（3）为什么危险：你在 free(p) 之后读 *p，读到的其实已经是别人的内存了。别人往那儿写点什么，你的程序就会看到莫名其妙的值，甚至可能因为读到非法地址而直接崩溃。

小结#

内存管理非常强大，我们经常可以用它极致掌控每一个内存开始和结束位置，进行极限压缩内存。

习题#

1. 猜输出#

下面这个程序会输出什么？先自己在心里算一遍，再运行验证。

#include <stdio.h>
#include <stdlib.h>
int main(){
	int *a = (int*)malloc(5 * sizeof(int));
	for (int i = 0; i < 5; i++) a[i] = i * i;

	int *b = (int*)realloc(a, 10 * sizeof(int));
	printf("%d %d\n", b[0], b[4]);

	free(b);
	return 0;
}

本题推荐最大时长：3分钟

答案

运行结果：

0 16

realloc 扩容的时候会把老数据带过去：b[0] 还是 0 * 0 = 0，b[4] 还是 4 * 4 = 16。

2. 编程题：运行时才知道长度的数组#

输入第一行一个整数 n（1 <= n <= 100000），第二行 n 个整数。要求用 malloc（C++ 用 new[]）申请正好 n 个 int 的空间把它们存下来，然后输出最大值和总和。

本题推荐最大时长：8分钟
题目输入案例：
5
3 7 1 9 4
输出结果案例：9 24

答案

C#

#include <stdio.h>
#include <stdlib.h>
int main(){
	int n;
	if (scanf("%d", &n) != 1 || n <= 0) return 0;

	int *a = (int*)malloc(n * sizeof(int));		// 申请 n 个 int
	if (a == NULL) return 1;

	for (int i = 0; i < n; i++) scanf("%d", &a[i]);

	int mx = a[0];
	long long sum = 0;				// 100000 个数相加可能超出 int
	for (int i = 0; i < n; i++) {
		if (a[i] > mx) mx = a[i];
		sum += a[i];
	}
	printf("%d %lld\n", mx, sum);

	free(a);		// 一定要释放！检查你的答案有没有全部释放！
	return 0;
}

C++#

#include <iostream>
int main(){
	int n;
	std::cin >> n;

	int *a = new int[n];
	for (int i = 0; i < n; i++) std::cin >> a[i];

	int mx = a[0];
	long long sum = 0;
	for (int i = 0; i < n; i++) {
		if (a[i] > mx) mx = a[i];
		sum += a[i];
	}
	std::cout << mx << " " << sum << "\n";

	delete[] a;		// 一定要释放！检查你的答案有没有全部释放！
	return 0;
}
